# Authorization

## Current model

Authorization is enforced in the React application based on the current user's `role`.

The application explicitly recognizes `Guest` and treats non-Guest authenticated users as authorized for protected application routes.

The seeded user database contains:

- `Admin`
- `Operator`

Guest is generated by the application.

## Protected routes

| Route | Guest |
|---|---|
| `/` | Allowed |
| `/3d` | Denied |
| `/alerts` | Denied |
| `/maneuvers` | Denied |

## Important limitation

This is **frontend route gating**, not security-grade authorization. A user who controls browser state can potentially manipulate client-side state.

No backend authorization middleware exists because the backend is not implemented.

## Production requirement

Authorization must be moved to the server/API boundary. The frontend should continue to hide unavailable UI, but the backend must independently enforce resource permissions.
